# 자주 발생하는 오류

- **operation ID 접미사를 기억해서 사용**: 같은 이름의 `_1`, `_2`가 명세 업데이트로 달라질 수 있습니다. `search_operations` 결과의 method/path/description과 스키마를 함께 확인하세요.
- **ID 필터 API를 전체 조회로 사용**: `ids` 필수 여부를 먼저 확인합니다. ID를 알 수 없으면 조회용 API부터 찾습니다.
- **타입을 자동 변환한다고 가정**: 정수 필드의 `"1"`, boolean 필드의 `"true"` 같은 문자열은 차단될 수 있습니다. 정확한 JSON 타입을 사용합니다.
- **query 구조체를 임의로 전달**: 일부 URI template 매개변수는 JSON 문자열을 요구합니다. `fields`와 `timeRange`도 현재 스키마가 문자열이면 JSON 문자열로 인코딩해서 전달합니다.
- **불명확한 타입을 추측**: `modifyBidWeightUsingPUT`의 `codes`는 공식 `type: ref`가 미해결이므로 전달 시 차단됩니다. 배열이나 CSV로 우회하지 말고 `manual-overrides`를 확인합니다.
- **모든 POST를 조회로 간주**: 추정·보고서 생성처럼 읽기 성격이 있는 기능도 POST이면 쓰기 조건을 요구합니다. `execute_read_operation`은 GET만 허용합니다.
- **HTTP 200 또는 빈 failures를 전체 성공으로 간주**: 본문의 업무 오류와 항목별 상태까지 읽습니다.
- **통신 실패 후 쓰기를 바로 재시도**: 먼저 반영 여부를 조회해 중복 등록을 피합니다.
- **저장 실패를 API 실행 실패로 판단**: `meta.cache_error`가 있으면 반환된 body와 HTTP 상태를 확인합니다. API 실행 뒤의 로컬 저장 실패일 수 있으므로 쓰기를 그대로 재실행하지 않습니다.
- **임의 경로 저장·읽기**: 저장은 새 `.json` 파일명만, 읽기는 현재 서버가 반환한 `meta.saved_to`만 사용합니다. 이전 프로세스의 경로는 재사용할 수 없습니다.
- **고객 ID 마스킹을 모든 데이터 익명화로 이해**: 나머지 응답에는 광고명·키워드·성과 등 실제 정보가 남을 수 있습니다.
- **문서 조회 성공을 인증 성공으로 이해**: 메타데이터 도구에는 API 키가 필요하지 않습니다. 실제 GET 성공으로 네이버 연결을 별도 확인합니다.
