# 명세 보정

공식 Swagger 사본에서 일부 매개변수는 타입이 빠져 있거나 `type: ref`처럼 일반적인 JSON 타입이 아닐 수 있습니다. 서버는 지원 가능한 항목에 근거를 기록한 보정을 적용하며, 모든 불명확한 입력을 임의로 허용하지 않습니다.

`get_operation_schema(operation_key)`의 매개변수에 `_manual_override_reason`이 있으면 원본 명세 이외의 보정이 적용된 것입니다. 실제 적용 내용은 이 응답과 패키지의 `spec.py`를 확인합니다. 과거 작업에서 관찰한 계정 값이나 보고서 ID는 다른 사용자의 입력 예제로 재사용하지 않습니다.

현재 보고서 GET/DELETE의 `reportJobId`는 공식 `ReportJobResponse` 정의에 근거해 `integer` / `int64`로 보정합니다. `ncc-heroes-ncc:modifyBidWeightUsingPUT`의 `codes`는 공식 명세가 `type: ref`이고 전송 형식을 확인할 근거가 부족하여 보정하지 않습니다. 배열·CSV라고 추측하지 않으며, 이 매개변수를 전달하면 네트워크 요청 전에 차단됩니다. 정합성 결과의 미해결 항목 1건은 이 제한을 드러내는 것입니다.

보정 타입으로 검증에 통과했다고 공식 서버가 그 값을 지원한다고 단정하지 마세요. 원본 설명, 관련 정의와 공식 예제에 근거가 있는지 확인합니다. 오류가 계속되면 원본 문서와 응답을 비교하고 검증을 우회하지 않습니다.

보정을 추가·변경하는 유지관리자는 공식 명세 사본과 보정 코드를 구분하고, 근거와 영향받는 operation을 기록한 뒤 검증 테스트를 실행해야 합니다. `validate_official_spec`은 내부 정합성 검사이며 명세 보정의 업무상 정확성까지 증명하지 않습니다.
