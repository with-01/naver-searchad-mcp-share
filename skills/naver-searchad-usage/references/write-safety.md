# 광고 변경 실행 조건

서버는 기본적으로 GET만 실행합니다. `execute_operation`이 도구 목록에 보여도 쓰기를 실행할 수 있다는 뜻은 아닙니다.

운영자가 서버 시작 시 `--allow-writes` 또는 `NAVER_SEARCHAD_ALLOW_WRITES=1`을 설정해야 하며, 각 POST/PUT/PATCH/DELETE 호출에는 다음 값도 필요합니다.

```python
confirm_action="NAVER_SEARCHAD_WRITE"
```

이 문자열은 호출 실수를 막는 조건입니다. 사용자 인증, 변경 승인 기록, 광고 계정별 접근 제어를 구현하지 않습니다. 클라이언트의 도구 승인 기능을 유지하고, 사용자의 명확한 지시 범위 안에서 실행합니다.

변경 전에 실제 대상 ID와 기존 상태, 적용할 값, 대상 수를 확인합니다. 사용자가 이미 범위와 값을 명시했다면 같은 승인을 반복해서 묻지 않습니다. 대상·금액·일괄 범위가 불명확하거나 기존 지시를 넘는 삭제라면 필요한 내용을 확인합니다.

일괄 작업의 한도는 해당 operation의 스키마·공식 설명으로 확인합니다. 모든 operation에 같은 배치 크기를 가정하지 않습니다. 각 배치의 응답을 기록하고 부분 실패가 생기면 완료·실패·미실행 항목을 구분합니다. 응답을 잃은 쓰기 작업은 반영 상태를 확인한 후 재시도합니다.

파일 기반 키워드 계획은 등록 100개·입찰가 수정 200개씩 나누고, 한 도구 호출은 `max_batches` 1~10 범위만 실행합니다. 실패·불명확한 결과는 자동 재시도하지 않습니다. 응답을 잃으면 `get_keyword_batch_status`부터 확인하고, `stopped` 상태에서는 네이버 반영 결과를 대조합니다. 상세 절차는 [bulk-keywords](bulk-keywords.md)를 확인하세요.

일시정지, 삭제, 예산 변경의 영향은 대상 API와 현재 계정 상태에 따라 다릅니다. 하위 항목의 자동 삭제나 성과 데이터 소실을 근거 없이 단정하지 않습니다. 사용자가 원하는 효과를 해당 API가 제공하는지 확인합니다.

HTTP 2xx와 `failures` 배열만으로 전체 성공을 확정하지 마세요. 원본 body의 오류와 항목별 상태를 확인하고, 필요한 경우 GET으로 반영 여부를 다시 조회합니다.
