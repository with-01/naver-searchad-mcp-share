# 대량 키워드 처리와 토큰 측정

가장 큰 비용 원인은 키워드 JSON을 모델이 매번 작성하는 입력입니다. 응답 저장만으로는 줄지 않습니다. 0.3.0은 운영자가 허용한 폴더의 JSON을 서버가 읽고, 원문·쿼리·계정을 묶은 해시로 계획을 고정합니다. 파일이 나중에 바뀌어도 검토한 계획의 데이터는 바뀌지 않습니다.

서버는 공식 한도인 등록 100개·수정 200개 단위로 요청합니다. 도구 호출 한 번에 기본 1회, 명시적으로 지정하면 최대 10회 실행합니다. `start_offset` 일치 검사로 같은 범위 재실행을 막습니다. 계획·진행 상태는 서버 프로세스에만 보관되므로 재시작 후에는 네이버 현황을 대조해야 합니다. 중단된 계획은 자동 재개하지 않습니다.

## 2만 건 모의 데이터 측정

비교 기준은 `ea03195b9db6a34f2e67e2431dc28013d7171a48`(0.2.0)의 직접 JSON 요청/응답 형식과 0.3.0의 파일 계획입니다. 실제 광고 계정 요청 없이 `httpx.MockTransport`로 실행했습니다. 입력은 합성 키워드·ID·입찰가를 가진 JSON 파일입니다. 양쪽 모두 같은 100/200개 단위이며 개선 후 `max_batches=10`입니다.

| 작업 | 기존 입력 토큰 | 개선 입력 토큰 | 기존 출력 토큰 | 개선 출력 토큰 |
|---|---:|---:|---:|---:|
| 키워드 20,000개 등록 | 448,200 | 약 1,800 | 802,800 | 약 18,700 |
| 키워드 20,000개 입찰가 수정 | 663,800 | 약 900 | 781,400 | 약 9,500 |

MCP 호출 수는 등록 200회→21회, 수정 100회→11회(준비 1회 포함)로 줄었습니다. 네이버 API 요청 수는 각각 200회·100회로 동일합니다. 전체 20,000개가 실패한 응답의 토큰 추정은 약 579,000→230으로 감소했고 원문은 전부 캐시에 보존했습니다. 입찰가 수정 스키마는 전체 2,139→입력 전용 891토큰입니다.

토크나이저는 `tiktoken`의 `o200k_base`입니다. 공백을 최소화한 도구 인수와 결과 JSON **한 표현**만 계산했으며, 메시지 포장·MCP 스키마 목록·대화 기록·내부 추론·도구 선택·클라이언트별 중복 처리·캐시 과금은 포함하지 않습니다. 임시 파일명과 계획 ID 때문에 실행마다 소폭 달라집니다. 입찰가 입력 검증 오류 수정의 성공 효과와 토큰 효과는 별개입니다. 이 수치를 실제 GPT/Claude 청구량이나 전체 대화 절감률로 해석하면 안 됩니다.

파일을 모델이 먼저 2만 줄 생성하거나 통째로 읽으면 그 단계의 토큰은 그대로 발생합니다. 기존 업무 데이터 파일을 코드로 변환하고, 모델에는 경로·처리 범위·요약만 전달하는 조건에서 효과가 큽니다. API 요금이나 네이버 호출 제한은 줄지 않습니다.

## 재현

저장소 이력을 포함한 checkout에서 실행합니다. `tiktoken`은 측정용 선택 의존성이며 서버 실행에는 필요하지 않습니다.

```powershell
python -m pip install -e ".[dev]" tiktoken
python scripts/benchmark_payloads.py
python -m pytest
```

검증은 2만 행의 정확한 분할/복원, 페이지 경계, 실패 필터, 파일 경로 제한, 변경 전 전체 검증, 계획 해시/계정/중복 실행 차단, 중단 후 무재시도를 포함합니다. 기존의 문자열 검색식 '토큰 절감 금지' 검사는 제거하고 실제 원문 보존·부분 조회 회귀 테스트로 확인합니다.

## 조회 및 호환성

- 저장된 목록은 실패 필터 후 페이지를 적용합니다. 기본 20개·최대 100개·본문 20,000바이트이며 `next_offset`으로 이어서 읽습니다. 한 항목이 너무 크면 건너뛰지 않고 `fields` 지정을 요구합니다.
- 객체 안의 목록은 `collection_key`로 선택합니다. 원문은 캐시에 그대로 남고 사용자 ID 마스킹 정책은 유지됩니다.
- HTTP 오류 응답도 큰 경우 저장합니다. 실패 미리 보기는 최대 5개이며 전체 실패 수를 별도로 반환합니다. `ok_count`는 알려진 실패 상태로 분류하지 않은 수이며 성공 확정 수가 아닙니다.
- `structuredContent`와 JSON 텍스트는 [MCP 공식 호환성 권고](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#structured-content)에 따라 함께 유지합니다. 실제 클라이언트가 두 표현을 어떻게 처리하고 과금하는지는 이 측정으로 단정하지 않습니다.
- ChatGPT 웹용 원격 서버는 운영자가 파일을 서버에 배치해야 합니다. 사용자 PC의 파일을 자동으로 읽는 기능이나 웹 업로드 UI는 포함하지 않습니다. 사용자별 서버/키 분리와 HTTPS 인증 게이트웨이 요건은 [연결 안내](clients.md)를 따릅니다.
